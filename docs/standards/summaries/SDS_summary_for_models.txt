SDS SUMMARY FOR MODEL INPUTS — I-SCEET
Source: Software Design Standards (SDS), v2.0, BASELINE, 2026-07-03.
Applies to: M2 software architecture and SDDD/LLR generation.

Purpose: SDS defines the mandatory structure, design constraints, module decomposition rules, interface standards, complexity limits, data design rules, and control-flow rules for the SDDD generated by M2.

SDDD structure: The SDDD shall contain five sections: I Introduction, II Architecture, III Referenced Documents, IV Requirements, V Summary. Section II includes Static Architecture (functional decomposition, data coupling, control coupling, target constraints) and Dynamic Architecture (data/control flow narrative). Section III contains only references actually used in JUS tags. Section IV is organized by function and includes Prototype, Parameters table, Pre-conditions, Called Functions, Input/Output Data, Data Dictionary tags, and one or more LLR blocks. Section V maps LLRs to HLRs.

Module rules: Use lowercase_snake_case modules/files such as flash_driver.c/.h. Each module should implement one subsystem, have high cohesion, low coupling, defined public interfaces through .h files, complete HLR coverage, and independent testability. Every HLR shall be implemented by at least one design element/LLR.

Interface rules: Public functions are declared in headers. Function interfaces define exact prototype, typed parameters, return status, input/output data, preconditions, called functions, and error behavior. Inter-module communication shall occur through defined interfaces only, not by direct access to another module’s internal data.

Complexity limits: Maximum 20 functions per module, 500 lines per source file, 100 lines per header, 5 module dependencies, cyclomatic complexity <=10 per normal function, <=4 for safety-critical ISR, target <=5, nesting <=4 general and <=2 ISR, function length <=60 lines except justified state machines, max 6 parameters, max 2 return points.

STM32F303 execution model: initialization order is reset, clock to 72MHz, GPIO, UART 115200, Flash, CRC-32 verification, boot jump or update/error mode. Interrupts must be analyzable, bounded, and compatible with DAL A verification.
